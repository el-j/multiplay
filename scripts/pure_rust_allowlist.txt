# ==============================================================================
# Multiplay Native-Code Allowlist
# ==============================================================================
# Policy:
# multiplay forbids vendored or bundled third-party C/C++ libraries (OpenSSL,
# SQLite, FFmpeg, aws-lc, libpulse, or cmake-driven builds). Audio decoding
# (symphonia), storage (redb) and DSP (rubato, realfft, biquad) are pure Rust.
#
# Permitted: thin bindings to libraries the host OS provides (audio, windowing,
# graphics, system calls). Every crate that links native code (`-sys`) or
# compiles/locates native code at build time (direct dependent of cc, cmake,
# pkg-config, bindgen, ...) must be listed here with a justification.
# `scripts/verify_pure_rust.sh` enforces this list on all targets.
#
# Format:  crate-name: justification
# ==============================================================================

# --- Linux -------------------------------------------------------------------
alsa-sys: Links the OS libasound for cpal audio output on Linux (located via pkg-config)
wayland-sys: Binds the OS libwayland-client for winit on Linux (located via pkg-config)
wayland-backend: Wayland protocol backend for winit; build script uses cc for OS libwayland glue
khronos-egl: Binds the OS libEGL for wgpu's GL backend on Linux (located via pkg-config)
x11-dl: Loads the OS libX11 family at runtime (dlopen) for winit on Linux; build script only queries pkg-config, no C is compiled
linux-raw-sys: Pure-Rust Linux syscall definitions for rustix (no C code)
netlink-sys: Pure-Rust Linux netlink sockets (kernel interface, no C library, no build script) for libp2p's interface watcher (if-watch) in the P2P mesh

# --- macOS -------------------------------------------------------------------
core-foundation-sys: Binds the OS CoreFoundation framework on macOS
security-framework-sys: Binds the OS Security framework so rustls checks certificates against the system trust store (reqwest platform verifier); no build script, no C code
objc-sys: Binds the OS Objective-C runtime for winit/eframe on macOS
system-configuration-sys: Binds the OS SystemConfiguration framework on macOS (build script only links the framework) so libp2p's interface watcher sees network changes in the P2P mesh

# --- Windows -----------------------------------------------------------------
windows-sys: Raw bindings to OS Win32 / WASAPI APIs (no C code)

# --- WebAssembly (cross-compilation only) -----------------------------------
js-sys: Bindings to the host JavaScript engine for wasm targets
web-sys: Bindings to browser Web APIs for wasm targets

# --- Android (cross-compilation only, via winit/cpal) -----------------------
jni-sys: Java Native Interface bindings on Android
ndk-sys: Android NDK OS bindings for cpal and winit
android-activity: Android activity glue for winit; compiles the NDK's native_app_glue C file (Android only)

# --- Graphics debugging (via wgpu) ------------------------------------------
renderdoc-sys: RenderDoc in-application API header bindings for wgpu; loaded only if RenderDoc is present

# --- Documented exception -----------------------------------------------------
# ring is NOT pure Rust: it compiles BoringSSL-derived C and assembly crypto
# primitives with cc. It is the only crypto provider rustls supports without
# aws-lc. Accepted until a pure-Rust provider (e.g. rustls-rustcrypto) is
# production-ready; tracked under TASK-124 (supply-chain hygiene).
ring: EXCEPTION - rustls crypto provider; compiles bundled C/asm primitives via cc
